# SiteLedger first milestone

Use the sibling commercial-cases.json as independent acceptance examples. Each example starts with zero prior postings unless a prior quantity is specified. These are synthetic inputs and expected outputs for development. Business owner review is pending.

## Walk the transactions

1. Save the allowance offline, restart, and reconnect. Resubmit the same client identifier after a lost acknowledgment. Expect one claim, a traceable review by each assigned reviewer, and zero actual cost until Head Office pays. Retry the payment and reconcile the single posting on the project comparison.
2. Route the single-day rental. Its tool reference and rental period follow the payment posting. Even this small rental requires PM review.
3. Select the live order and view both material estimate lines. Raise a numbered site indent for company cable and preserve the initiator and purpose. Try the client panel separately and expect the indent to be blocked. The cable request deliberately exceeds estimate to exercise reporting. For this fixture assume the authorized reviewers accept the request.
4. Apply the process assigned to the project. Stores receives the indent only after its final approval. Link a purchase for any shortage. Import the two delivery challans separately. Inspect the comparison after each import and retry the second import. The purchase link, site receipt and repeated import each add zero incremental project cost. Preserve the original estimate and drill from the variance to both source lines.
5. Track dispatched and acknowledged quantities separately so stores can see material still in transit. A site receipt against the first challan acknowledges 60 m. With both challans dispatched, the site has acknowledged 60 m and 50 m awaits acknowledgment. Confirm the receipt evidence and responsible designation with the site lead.
6. Start the independent billing example with ten PM-certified units. Issue one part bill, check work, tax, retention and net due, then test the remaining certification ceiling. A challan alone supplies zero billable certified quantity.

## Permission examples

| Actor | In-scope action | Expected control |
| --- | --- | --- |
| Technician | Submit own allowance on assigned project | Sending the same queued version twice creates one claim |
| Supervisor and Site Engineer | Review assigned claim in sequence | An out-of-turn decision cannot advance the claim |
| Project Manager | Review routed rental and certify measured work | Certification above available approved quantity fails |
| Head Office | Mark payable, record payment and issue a certified bill | Payment retry creates one posting and a draft bill contributes zero issued value |
| Designated indent reviewer | Decide the current step on an assigned project | A reviewer from a different project's process cannot advance the indent |
| Stores | Act on a fully approved indent | Pending approval keeps the indent out of the actionable stores queue |
| Approved contractor | View own assigned subcontract package | Another contractor's package and employee claims are outside scope |

## Inputs needed for the first integration

The project plan selects offline allowance through payment as the first application workflow. The materials fixture establishes an additional accounting boundary for that implementation. Use one material posting per linked Tally challan line across reports. Confirm how existing material issues map to those lines before enabling both sources.

Head Office and the PM should confirm the overhead allowance and treatment of incurred costs above budget. Head Office should verify the illustrated GST and retention basis. Operations should supply one actual project approval process and its designation assignments. Request a redacted Tally export with stable voucher and line identifiers, an amended or cancelled challan, and a partial delivery before choosing import keys or correction rules. The example keys and approval designations are illustrative.
